# Mova Performance Baseline & Acceptance Stage 1 Plan

> Scope: establish low-intrusion observability, reproducible fixture data, smoke baselines, budgets, and acceptance commands before large performance refactors. This stage intentionally does **not** optimize Canvas/Export/FileTree/AI runtime internals at scale.

## Inputs reviewed

- Performance research report: `mova-zed-vs/research/performance-overhaul-zed-vscode.md`
- Read-only subagent reviews:
  - `subagent-readonly/test-script-structure.md`
  - `subagent-readonly/frontend-perf-instrumentation.md`
  - `subagent-readonly/rust-tauri-perf-points.md`
  - `subagent-readonly/scope-risk-review.md`

## Goals

- Add a small TypeScript performance utility for marks, measures, summaries, JSON reports, and Markdown reports.
- Add deterministic small/medium/large test fixtures for projects, animations, chat messages, and file trees.
- Add Vitest smoke baselines for store/helper operations that do not call real AI providers or real Tauri IPC.
- Add a script entrypoint that can regenerate a Stage 1 baseline report.
- Document budgets, validation commands, and how later optimization worktrees should use the measurements.

## Non-goals

- No large CanvasArea, ExportWizard, FileTree, ToolRunner, or AgentOrchestrator refactors.
- No provider calls, network calls, browser automation, or Playwright.
- No new heavyweight dependencies.
- No Rust command/API changes in Stage 1.
- No project schema, settings persist schema, or chat history schema migrations.

## Stage 1 measurable metrics

| Metric | What it measures | Initial smoke budget | Why included |
|---|---|---:|---|
| `project.large.map-rust-project` | Rust project payload to frontend model conversion on a large fixture | 1500 ms | Project open/load normalization baseline |
| `project.large.serialize-for-rust` | Frontend project model to Rust payload conversion on a large fixture | 1500 ms | Save/autosave payload conversion baseline |
| `project.store.medium.load-and-update` | Project store load plus character add/update/tag mutations | 1000 ms | Store update overhead baseline |
| `animation.frames.large.set-and-mutate` | Large animation `setAnimations`, reorder, update, duplicate, copy/paste | 1500 ms | Timeline/frame operation baseline |
| `chat.streaming-draft.large.update-message` | Simulated streaming assistant draft updates in chat store | 1500 ms | Streaming update overhead without provider calls |
| `file-tree.large.filter-and-count` | Pure file-tree search/filter/count helper on a large tree fixture | 1000 ms | File-tree transformation/search baseline |

Budgets are deliberately broad smoke budgets. They are regression tripwires, not precise benchmarks. Later optimization stages should record pre/post reports on the same machine and compare the JSON summaries rather than overfitting to the initial thresholds.

## Acceptance commands

Run from `Mova/`:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm perf:baseline
```

Rust is not modified in Stage 1. If a later worktree changes `Mova/src-tauri`, also run:

```bash
cd Mova/src-tauri
cargo test --lib
```

## How later optimization stages should use these metrics

1. Before changing a hotspot, run `pnpm perf:baseline` and save the generated JSON/Markdown report.
2. Implement one bounded optimization area per worktree, preferably one owner per hotspot family.
3. Run `pnpm perf:baseline` again and compare metric `p95Ms`, `meanMs`, and correctness assertions.
4. Update budgets only after repeated measurements show stable headroom; do not loosen budgets to hide regressions.
5. Add new metrics before optimizing new areas such as Canvas frame time, export/GIF, image split/background removal, real project file tree scans, or AI runtime adapter events.

## Rust/Tauri follow-up plan

No Rust code is changed in this stage. The read-only Rust review recommends future low-risk perf smoke via existing unit tests or `#[ignore]` tests using `Instant` for:

- `split_frames` on 4x4 and 8x8 sheets.
- `remove_magenta_background` on 1024/2048px fixtures.
- `sprite_sheet::compose` on 32/64/128 frame fixtures.
- `export_gif` on low-color and high-color frame sets.
- `list_project_files` on temporary 1k/5k file trees.

These should remain separate from default tests unless the fixtures are very small and stable.

## Risk controls

- The new perf smoke uses mocked Tauri IPC and deterministic fixtures; it does not call real providers or filesystem watchers.
- The file-tree production change is limited to extracting existing search/filter logic into a pure helper.
- Perf thresholds are intentionally loose to avoid flaky CI/dev runs.
- No new npm/cargo dependency is introduced.
- AI runtime core files are not modified.
